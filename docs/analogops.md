# アナログ環境での運転・設定

このデコーダソフトウェアは、アナログ環境での走行にある程度対応しております。
<br>そのため、本デコーダソフトウェアを搭載した車両を、DCC環境を用意できない場所や、DCCの使用を禁止されている場所に持ち込んでも支障なく運転を楽しんでいただくことができます。

しかし、DCCデコーダに使用しているマイコンや内部回路の動作電圧の都合などから、操作は通常のアナログ車両と若干異なる方法となります。

本デコーダソフトウェアでは、ボリュームを最大まで回しても速度を抑制して走行可能な設定や、加速時における加速度を設定できるため、調整次第ではアナログ環境下でもリアルな運転を楽しむことも可能です。

---

## アナログ走行の方法

アナログ走行を行うためには、下記の方法を行います。

  * パワーパックのボリュームを80%程度まで回す
    <br>パワーパックボリュームを回しても、後述する加速度の設定ですぐには動き出さないので問題ありません。
    <br>また、最高速度近くで暴走することもありません。
  * 車両の動き出しを待つ
    <br>デコーダが線路電圧・走行方向を判別して動作を開始します。
  * 速度を調整する
    <br>パワーパックのボリュームを動かして速度を微調整します。
    <br>通常のアナログ車両の走行と異なり、パワーパックのボリュームを絞りすぎるとデコーダが停止して車両が止まってしまいます。

## PWM入力の時間積算による方向判定・速度制御

PA2・PA4の入力エッジと既存のTCB0タイマーから、各状態の継続時間を積算します。
PA2=1 / PA4=0を方向1、PA2=0 / PA4=1を方向2、両方0をオフとして扱います。
両方1の時間も測定窓の全時間に含めますが、通電時間には加えません。
想定入力は20kHz周辺、オフ時は入力がプルダウンされ、基板のコンデンサでマイコン電源が維持される構成です。

`main.c`の既存RTCクロック供給から`analogPollerClkReceiver()`を呼び、モーター版では512回、ファンクション限定版では256回ごとに測定結果を更新します。
RTC通知の公称周波数はモーター版が1,024Hz、ファンクション限定版が512Hzなので、いずれも更新間隔は約0.5秒です。
メインループの遅延やサービスモード中のクロック供給停止がある場合、更新間隔は延びます。
デューティの分母には通知回数ではなく、TCB0で測った実際の経過時間を使用します。
TCB0の周期・クロックは変更せず、周回割り込みによってエッジのない期間も積算します。

読み取り部はCV値を参照せず、`analogDuty()`で0〜255を返します。
モーター版では`setspeed_analog()`で次の整数演算により目標速度を求め、従来どおり
`clock_receiver_train_ctrl()`でCV59に従って加減速します。

```c
speed = ((uint16_t)CV58 * analogDuty() + 127U) / 255U;
```

- 起動時は方向未確定・デューティ0です。初回測定が完了するまでアナログ速度は0です。
- 純直流は一方の極性が継続するため255（100%）となり、目標速度はCV58です。
- 無通電ではデューティ0とし、最後の有効な方向を保持します。
- 測定窓内に両方向の通電時間がある場合、DCCまたは方向変更途中としてデューティ0にします。
  次の単一極性の窓で方向とデューティを更新します。
- 停止も約0.5秒の更新とCV59による減速を経由します。別途の高速無通電停止は追加していません。
- アナログ速度の値1は通常の低速値です。デジタル側の値1による非常停止は維持しています。
- モーター側のBEMF補正や低速変調は既存のままなので、この目標速度と最終出力デューティ、実車速度は必ずしも比例しません。
- DCC受信によるモード判定とCV29によるアナログ運転の許可は既存のままです。
  アナログ判定中はRailcomのカットアウト送信予約を行いません。DCCの受信処理は継続します。
- ATtiny806のファンクション限定版も、Studio版・Arduino版ともに同じ時間積算方式を使用します。
  確定した`analogDirection()`を既存の`funcCtrlAnalog()`へ渡し、方向に応じたファンクション出力を切り替えます。
  デューティによるファンクション出力の調光は追加していません。
  無通電・極性混在では最後の有効方向を保持するため、ファンクション側にもその方向が渡されます。
  最初の有効な測定窓が完了するまでは方向0です。
  既存のDCC未受信タイムアウト800通知は変更していないため、ファンクション版のアナログモード移行は公称約1.56秒です。

### 検証

`python3 tests/run_analog_tests.py`で、実装本体をホスト用の模擬AVRレジスターと組み合わせてテストできます。
Cコンパイラー（既定は`cc`、`CC`環境変数で指定可能）とAddressSanitizer / UndefinedBehaviorSanitizerが必要です。
Studio用・Arduino用のモーター版とファンクション限定版の各ソースについて、20kHzの全251パルス幅、周辺周波数、純直流、
無通電、極性混在、タイマー周回、RTC更新境界、DCCパケット受信を検証します。モーター版ではさらにCV58の全256値、CV59による加減速を検証します。

このテストは割り込み遅延や実際の電気波形を再現しません。
20kHzでは通常毎秒4万回の入力割り込みになるため、実機では特に短いオン／オフパルス、
他の割り込みとの競合、DCC・Railcomへの復帰を確認してください。
TCB0の周回を取りこぼさないため、割り込み禁止時間は10.6496ms未満である必要があります。
測定可能な最短パルス幅はタイマーの0.2µs分解能だけでは決まらず、実際の割り込み応答時間に依存します。
